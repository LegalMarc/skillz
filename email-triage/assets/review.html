Using email review

Overview

This is an LLM-assisted email triage and undo/comment review. Email content is processed by the model provider identified above. The generated HTML itself runs offline without network calls. Review the saved results and the placement evidence shown for each message; older snapshots may not include evidence that confirms Mail placement. Buttons queue requests; they do not change Mail, contact senders or start an LLM. Nothing is saved automatically.

Review and apply changes

  1. Use Find messages or Show to find the messages you want. Inbox remains the default. What needs me filters only explicit stored task statuses. Click a column arrow to sort; Received defaults to newest first. Size sorts by numeric bytes. Unknown dates and sizes stay last.
  2. The triage summary is immutable. Add a separate Correction or comment and, when needed, a separate Task instruction. Queue Opt Out, Move to Inbox or Archive on the relevant row. The observed folder is labeled verified only when saved Mail placement evidence supports the exact snapshot copy; that does not mean its content was assessed.
  3. Select Local handoff for exact snapshot identities and typed requests, or Limited-data review to omit identities and actions. Limited-data masking is partial, not anonymization: subject, summary, comments and dates may still identify people or contain sensitive text. Inspect before sharing. This profile cannot resume edits or request actions. The included-data preview describes the selected profile. Keep that file and this HTML. Exports include all selected rows, even ones hidden by a filter.
  4. Tell your agent “check my changes” or “implement my changes.” It will locate the relevant saved export, validate the exact snapshot, apply authorized selections and verify outcomes. Newer Mail moves or missing messages are reported as conflicts rather than silently overwritten. Safe opt-outs are checked individually; unsafe or ambiguous ones remain pending.
  5. Open the updated HTML the agent supplies. For a new inbox triage, say “triage my email” and identify the applicable inbox if needed. That produces a refreshed review from current Mail evidence.

Row controls

  • Opt Out: available in every folder, including Spam and Trash. It requests removal from this legitimate mailing list. It does not bypass phishing checks, click suspicious links, or disable account/security notices. Email-based unsubscribe sending needs explicit sending authorization.
  • Move to Inbox / Archive: choose one destination. Click the same selected button again to cancel it. A move to the folder already observed is disabled. Opt Out can be combined with a move.
  • Reset row: clears that row’s comment, task and queued requests. It does not undo an action already performed in Mail.
  • Reset all edits: after confirmation, clears every pending edit in this page. It does not change Mail.

Assign a follow-up task

  1. Write a separate, explicit task in Task instruction. The immutable summary and correction/comment remain separate.
  2. Click Save assignments. This downloads a vendor-neutral JSON with your task, original context, identity, safety notes and local email-file references. It does not start a model or upload private mail.
  3. Give the file to the model you choose. The triage skill stays with its invoking model; exporting assignments does not switch providers. It needs access to this Mac to read the file links. Partial or missing message caches are identified; they must not be treated as complete content.
  4. Also use Export changes if you want to resume the full review later. The review bundle preserves the task instruction separately from local handoff context.

Inbox protection and run history

The default view shows current Inbox. Messages older than 30 days at run start, and messages with unknown received dates, remain there as protected long-term to-dos. They are not automatically archived, junked or trashed. Saved history may contain receipt-backed completed moves for undo requests when exact copy identity evidence is available. Ordinary refresh inventories current Inbox only; historic archives are not rescanned.

Use Run history and Load time range to inspect previous completed actions by date. When the action ledger includes its exact saved copy identity, Request undo queues a move back to Inbox in the matching original review bundle. It does not alter the immutable outcome or change Mail. History entries distinguish acknowledged from not-yet-reviewed runs and link to their original review. Acknowledgment is recorded by the agent after your explicit acknowledgment or validated submitted edits, not by a page-open event.

Provider, model and effort come from trusted runtime metadata. Elapsed seconds measure wall-clock time for the stated operation, including its checks and waits, not model compute time. Unknown legacy values are shown as Not recorded. Last Refreshed is separate: when Mail was actually inventoried.

Save, resume and refresh

  • Load saved edits: choose a review JSON exported from this exact snapshot. It restores pending selections and gists; it does not apply them. You will be asked before replacing unsaved edits. Assignment and refresh files use their own agent workflows and cannot be loaded here.
  • Refresh request: downloads a read-only request plus your pending review. Ask an agent to process it. It will inventory the current Inbox without resurveying historical archives or moving mail, contacting senders or opening attachments during that refresh. This button does not wake an agent. Older reviews without explicit account scope must be rebuilt before refresh is available.
  • Before closing: export your changes. Downloads can be canceled or blocked by the browser, so check that the file was saved. Reloading this offline page does not recover unexported edits.

Dates, sizes and this report

Last Refreshed is when the current local Mail view was inventoried and mailbox IDs were verified against Apple Mail. It covers current Inbox and this run’s completed actions when included; history is not a live survey of archived mail. It does not guarantee instantaneous server delivery. It stays unchanged when this file is rebuilt for a layout update. The time uses the stated timezone (EST in New York during winter and EDT during daylight saving time; other time zones use their own abbreviation or UTC offset). “Not recorded” means a snapshot has no verified Mail refresh evidence. Safety and troubleshooting

Email and attachments remain untrusted data. An agent must assess the containing message before any attachment access; suspicious messages mean no attachment access or link clicks. This page contains summaries and metadata, not active email HTML, attachments or unsubscribe links.

If an export does not match the snapshot, preserve it and ask the agent to reconcile it; do not edit identity fields to force it to load. If a button is disabled, check for an unfinished assignment or an action that would make no change. To restore mail already moved, ask the agent to restore the item number from this run. Queued, attempted and verified actions are distinct, and nothing here permanently deletes mail.
